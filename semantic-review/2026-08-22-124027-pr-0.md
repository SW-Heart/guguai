# GuGu 2.0 AutoDL video generation

This change makes `grok-15` available as GuGu 2.0 and routes it through the AutoDL ComfyUI workflow. The server advertises 1–15 second generation, two aspect ratios, two quality levels, mixed image/audio references, and persists the upstream task ID through polling, archiving, and restart recovery. Credentials remain in server-side environment variables, and submit failures distinguish definitive client rejections from uncertain outcomes. **Watch for:** **confirmed** invalid quality values are silently converted to 768p, and the changed tests do not exercise the AutoDL payload or async lifecycle guarantees.  
**Verdict**: NEEDS_CHANGES

## High-level view

The capability profile keeps model ID `grok-15`, label GuGu 2.0, provider `autodl`, default duration 5, 1–15 second durations, 16:9/9:16 ratios, 480p/768p qualities, and 9-image/3-audio/12-total limits. The server persists the provider task ID before polling, so restart recovery can resume polling without another submission.

The submission boundary is fail-safe for ambiguous outcomes: a network failure or accepted response without a task ID remains charged and marked for reconciliation, while non-retryable 4xx responses are terminal. **Confirmed** risks remain in contract enforcement and regression protection: malformed quality input can reach the default resolution, and no deterministic test proves the exact AutoDL fields or the no-duplicate-submit lifecycle.

### GuGu 2.0 quality coercion

**confirmed** in `lib/video-capabilities.mjs`: the new GuGu 2.0 profile declares only `['768p', '480p']`, but `validateVideoRequest` treats any unrecognized `quality` or `resolution` as absent and selects `profile.qualities[0]`. The later membership check therefore cannot reject the bad value. For example, `quality: '1080p'` is accepted as `768p`; the AutoDL payload then emits `768p横` or `768p竖`. This violates the advertised four combinations and can produce a result different from the requested settings. Distinguish an omitted field from an invalid supplied field and return 400 for the latter.

### AutoDL contract and lifecycle coverage

**confirmed** by the changed test surface: `test/video-capabilities.test.mjs` asserts GuGu 2.0 catalog metadata but has no AutoDL payload assertion and no mocked submit/poll/archive/restart test. The implementation’s intended behavior is important enough to lock down: `buildAutodlPayload` must emit `480p横`, `768p横`, `480p竖`, or `768p竖`, use `ref_image_0..8` and `ref_audio_0..2`, and preserve the 12-item limit; `createAutodlVideo` must classify definitive submit 4xx errors as terminal and network/unknown outcomes as uncertain; recovery must poll the persisted task ID and never POST a second generation. Add these tests without making a real AutoDL request.
