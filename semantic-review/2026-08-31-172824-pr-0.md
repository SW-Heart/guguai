# Private R2-only business media pipeline

The business-media layer now uses one private R2 backend instead of selecting between OSS and R2, and the public configuration and upload contracts use provider-neutral names. Direct uploads are signed PUTs that are verified before promotion, while generated assets, reference inputs, previews, downloads, tail frames, and assembled videos converge on `objectKey`. Local-first desktop delivery and temporary `sourceUrl` fallback remain in place while archival retries move results into R2. **Watch for: confirmed — the renamed `/api/config` and direct-upload HTTP contracts have no direct HTTP regression coverage.**

**Verdict**: APPROVED

## High-level view

Metadata now points at `objectKey`, the primary bucket is private, and primary-object reads use expiring signatures. Upload intents carry temporary and final object keys, and promotion happens only after size, MIME, and file-signature checks.

Generated media remains available before archival finishes. The server prefers an existing local cache, then a signed R2 object, then the provider `sourceUrl`; Electron’s `local-ready` acknowledgment still marks local persistence complete and cancels archive retries.

Image inputs are copied into the dedicated reference R2 bucket, while video and audio inputs remain in the private primary bucket and receive the longer model-input signature lifetime.

**Confirmed:** the tests cover the clean R2-only baseline, provider-neutral persistence, local delivery, source fallback, and forbidden-identifier removal, but not the new configuration payload or signed PUT response through the HTTP server.

## Upload intents promote only verified private objects

`/api/files/uploads/init` returns a signed PUT URL plus the exact `Content-Type` header the signature expects. Completion verifies length, normalized MIME metadata, and magic bytes before copying to a server-generated final key; user-scoped intent lookup prevents cross-account completion. Private reads use signed GET URLs rather than a public primary-bucket URL.

Promotion is retry-safe: an existing final object is accepted only when size and MIME match the intent, while stale verifying intents are marked failed before temporary and final keys are scheduled for deletion. Content hashes are reused only within the same user and only for records with a remote object key.

## Local delivery remains ahead of R2 and provider fallback

`/direct`, `/content`, and reference restoration preserve local-first behavior. Pending generation assets can redirect to an unauthenticated provider URL or proxy an authenticated response without exposing provider credentials.

A generation result is persisted immediately with `sourceUrl`, then scheduled for R2 archival after the desktop grace period. A valid `local-ready` acknowledgment records size, SHA-256, and MIME type, clears `archivePending`, and cancels the retry timer; otherwise archive retries continue until the asset receives `objectKey` and `objectUploadedAt`.

## Reference staging separates image and audiovisual lifetimes

Images are copied into the dedicated reference bucket with its own cleanup lifecycle. Video and audio references stay in the primary private bucket and are signed with `R2_MODEL_INPUT_URL_EXPIRES_SECONDS`, defaulting to 7200 seconds; preview redirects sign the original image without an image-processing parameter.

## R2 upload HTTP contract lacks direct regression coverage

**Confirmed:** `test/uploads.test.mjs` exercises schema and store behavior only, and no test calls `/api/config` or `/api/files/uploads/init`. The suite does not lock down removal of `oss`, `directOssUpload`, and `storageProvider`, addition of `mediaStorageReady` and `directUpload`, or the init response’s PUT method and required `Content-Type`; add an HTTP test with a controllable R2 signer/client boundary so these contracts and the verify/promote flow run without real network access.
