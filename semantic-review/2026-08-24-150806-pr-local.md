# 专业短剧项目资产卡片与引用移除

本次未提交改动为专业短剧工作台加入项目资产面板、项目内移除、分镜素材引用和成片锁定，并通过 PATCH 保存项目 JSON。桌面指针 hover/键盘 focus 下，资产卡片会显示右上角移除按钮；移除路径只更新当前项目，不调用全局文件删除接口。当前不能批准：分镜资产加入路径调用了模块内不存在的 `addReferenceAssetToShot`，删除后的资源产物仍可能被重新收集，且成片锁定没有在服务端强制执行。Watch for：**confirmed** 分镜资产加入会在点击时抛 `ReferenceError`；**confirmed** 删除资源输出或引用文本后，资产/`@` 标记仍可能以不同形式回到生成链路；**confirmed** 已锁定项目可通过直接 API 请求继续写入。

**Verdict**: NEEDS_CHANGES

## High-level view

项目资产面板由 `renderProfessionalWorkspace` 重新生成 HTML，再由 `bindStoryboardWorkbench` 绑定事件；**confirmed** 动态渲染后的桌面 hover、叉号冒泡和键盘 focus 路径能够工作，移除确认后通过项目 PATCH 保存项目字段。

**confirmed** 删除边界是项目级的：前端没有调用 `/api/files/:id` 的 DELETE，服务端项目 PATCH 也只按当前用户和项目 ID 保存 JSON，因此普通场景不会物理删除其他项目或文件库中的原始文件。

**confirmed** 引用清理没有闭合：`seedProjectAssets` 仍会从项目资源的 `selectedTaskId` 补回资产，脚本文本中的 `@名称` 也没有同步处理；同时，加入当前分镜的调用链本身因缺少函数而失败。

**confirmed** 成片后的可见 UI 使用 disabled、`aria-disabled`、`contenteditable="false"` 和 `project.finalAssetId` 守卫，但服务端 PATCH、视频绑定、尾帧和合成接口没有同等锁定检查。现有测试全部通过，未覆盖这些 DOM 和接口场景。

### 资产卡片的 hover、删除点击与项目边界

**confirmed** 桌面指针路径是通的。`public/drama-studio.js:284-287` 为每个未锁定卡片生成真实的 `<button class="wb-asset-remove">×</button>`；`public/styles.css:1456-1459` 将其放在右上角，默认隐藏，在 `.wb-asset-tile:hover` 或 `:focus-within` 时恢复 opacity 和 `pointer-events`。`public/drama-studio.js:582-584` 绑定刚写入的卡片，叉号监听器先 `stopPropagation()` 再调用 `removeProjectAsset`，卡片 click 也跳过 `[data-project-asset-remove]`，所以叉号不会同时把素材应用到当前分镜。

**confirmed** 删除动作（`public/drama-studio.js:602-629`）只更新当前项目数组和分镜字段，然后 PATCH `/api/drama/projects/:id`。服务端 `server.mjs:1484-1499` 按当前用户读取项目并保存 `projectAssetIds`、分类和 `shots`；全局物理删除位于 `server.mjs:2022-2023` 的 `/api/files/:id` DELETE 分支，项目移除路径没有调用它。因此在资产不被重新收集的普通场景中，不会误删全局文件。

**confirmed** 触控和语义存在缺口。叉号在 `public/styles.css:1459` 默认 `pointer-events:none`，无 hover 的移动端不能先命中它来获得 `focus-within`；卡片又是 `role="button" tabindex="0"` 的 `<div>`，内部嵌套删除 `<button>`（`public/drama-studio.js:285`）。Tab 到叉号及卡片 `Enter`/`Space` 都有处理，但嵌套交互控件的屏幕阅读器语义不稳。若专业页面支持触控或无障碍验收，应改为非交互容器加独立操作，或让删除入口始终可命中。

### 分镜资产加入调用链与动态 HTML

**confirmed** `public/drama-studio.js:598` 的 `applyProjectAssetToShot` 和 `:647` 的指定分镜资产确认都会调用 `addReferenceAssetToShot`。模块顶部仅导入 `buildResourceImagePrompt`、`buildShotVideoPrompt`，全文没有该函数定义或导入；从资产卡片点击应用，或在“添加分镜参考素材”对话框确认选择，都会在这里抛 `ReferenceError`。这是运行时缺陷，`node --check` 无法发现，且调用发生在保存和 render 之前。

**confirmed** 动态 HTML 的绑定顺序本身没有问题：`renderProfessionalWorkspace`（`public/drama-studio.js:237-249`）重写工作台后，`bindStoryboardWorkbench` 才查询并绑定新节点。修复加入函数时需要让资产卡片入口和对话框入口共同写入 `referenceAssetIds`、必要的 `generation.referenceAssetIds` 和分类字段，否则加入与删除仍不对称。

### 引用清理与资产再出现

**confirmed** 删除时覆盖了 `professionalAssets.characters/locations`、`generation.referenceAssetIds`、首尾帧 ID、`referenceAssetIds`、`assetMentions` 和 `tailFrameAssetId`（`public/drama-studio.js:610-623`），并把受影响分镜标成 draft/stale；`shotReferenceIds`（`:1085-1086`）因此不会从这些普通字段读回该 ID。

**confirmed** 资源输出路径仍会把 ID 补回来。`seedProjectAssets`（`public/drama-studio.js:256-259`）每次专业工作台渲染时执行，除了分镜字段，还收集 `project.resources.map(resource => taskAsset(resource.selectedTaskId)?.id)`。`removeProjectAsset` 没有清除匹配资源的 `selectedTaskId` 或版本选中关系；如果被移除资产是某个项目资源的选中生成结果，删除 PATCH 成功后的 render 会再次把它放回 `projectAssetIds`，之后仍可能被保存。删除时需要解除资源关联，或持久化“已从项目排除”的状态。

**confirmed** 脚本文本也未同步清理。`removeProjectAsset` 只过滤 `shot.assetMentions`（`:617`），不修改 `shot.script`；重渲染的 `renderMentionEditorContent`（`:298-301`）会把没有元数据的原始 `@资产名` 当普通文本显示。`public/video-prompt.js:106-124` 只替换仍存在的 `assetMentions`，所以旧 `@资产名` 会原样进入脚本/Prompt。它不会凭自身重新建立资产 ID，但会造成 UI 已解除引用而 Prompt 仍携带旧标记；应明确删除 token，或把它降级为无语义文本并覆盖该行为。

**confirmed** 删除最后一个参考后保留 `REFERENCE` 或 `FIRST&LAST` 模式会让分镜暂时不可生成，这是 `professionalCapabilityState` 的显式失败门，不是资产再次出现。如果产品要求删除最后一张图后自动切回文本模式，需要另行定义；当前可作为可接受的显式约束。

### 成片锁定、事件冒泡与键盘场景

**confirmed** 前端锁定覆盖面较完整。`public/drama-studio.js:237-249` 根据 `finalAssetId` 添加 `is-locked`；资产添加/删除入口不渲染或设为 disabled，资产卡片改为 `aria-disabled="true"` 且不再设置 tabindex；分镜标题、删除、编辑器、生成参数、添加分镜和合成按钮也被禁用，编辑器设为 `contenteditable="false"`。正常页面操作不能绕过这些守卫。

**confirmed** 服务端没有同等边界。`server.mjs:1486-1499` 的项目 PATCH 未在 `finalAssetId` 存在时拒绝 `shots`、`projectAssetIds` 或其他编辑字段；`server.mjs:1702-1706` 的分镜视频绑定、尾帧提取和合成路由也没有锁定检查，`assembleDramaProject`（`:1061-1071`）没有拒绝重复合成。直接请求、旧页面的迟到请求或另一个客户端仍可在 UI 显示“已锁定”后改变项目；若锁定是产品不变量，服务端必须成为最终闸门。

### 测试覆盖与可接受风险

**confirmed** 已运行 `node --check public/drama-studio.js`、`node --check server.mjs` 和 `npm test`：130 个 Node 测试及 HTTP smoke test 全部通过。但没有浏览器 DOM 测试，未验证资产 hover/focus-within、叉号冒泡、触控、键盘、删除确认、资源再收集、未定义函数调用或锁定 API；这也是当前运行时缺陷能通过现有测试的原因。

可接受风险是：桌面、非锁定项目、资产不属于资源选中输出且不要求触控/屏幕阅读器时，移除按钮的行为链路清晰，确认文案也明确说明原始文件不会被删除。这个限定场景不足以支持整个专业短剧资产删除功能发布。
