# GuGu Agent 架构复核（2026-09-26）

参照：[OpenAI Skills 官方文档](https://developers.openai.com/api/docs/guides/tools-skills)、[Codex 技能与提示词实践](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)、[Agents 运行方式对照](https://developers.openai.com/api/docs/guides/agents)。GuGu 是自己的 OpenAI 兼容 Chat Completions 工具循环，并未使用 Codex harness；下表比较设计原则，不宣称两者能力相同。

| 方面 | 当前 GuGu | 结论 |
| --- | --- | --- |
| 通用任务 | 模型可直接回答，也可自由调用可用工具；创作技能不是必经流程。 | 符合通用助手的基本结构。可完成的外部操作仍受工具范围限制。 |
| 技能发现 | 默认只提供 `name` 和 `description`；模型需要时用 `skills_read` 读取正文或参考文件，界面选择只作为提示。 | 本次已纠正关键词强制装载完整技能的问题，符合渐进披露。 |
| 指令层级 | 核心运行约束在 system；工作区资料在 user 数据消息；技能正文经 tool 返回。 | 本次已纠正技能正文进入 system 的优先级问题。 |
| 上下文 | 默认仅提供作品和文档索引；正文用 `workspace_read` / `documents_read` 按需取。历史消息按字节裁剪，保留较早用户要求的简短索引。 | 默认上下文已收窄；尚无 Codex 式语义压缩，长任务可能丢失早期细节。 |
| 工具和权限 | 工具有参数校验、用户与工作区隔离，媒体生成有预检、费用确认与任务恢复。 | 对现有媒体工作流较完整；仍是固定工具集合，没有动态工具搜索、MCP、网页检索或隔离代码执行环境。 |
| 可靠性 | 会话、执行租约、工具历史和付费请求持久化；失败可恢复，关键边界有逻辑测试。 | 有生产所需的基本执行控制；缺少跨任务真实模型评测与端到端追踪分析。 |

## 本次修正

1. 移除 `runtime.mjs` 中按关键词自动读取 Skill 的分支。匹配规则只用于技能搜索排序，不替模型决定是否应用技能。
2. 把工作区资料从 system 移至 user 数据消息；不再将 Skill 正文复制到高优先级上下文。新一轮用户请求会隐藏上一轮工具返回的 Skill 正文，需要时可重新读取。
3. 缩短通用指令，删去默认要求视频创意草案、固定提问数等只适合特定任务的步骤；制作授权和费用确认仍由运行时约束。
4. 默认工作区上下文只保留索引；补强 `SKILL.md` 路径边界和目录优先级。

## 下一阶段优先项

1. **长任务记忆**：在保留用户约束和工具结果来源的前提下增加可检查的会话摘要或语义压缩，避免单纯字节裁剪造成遗忘。
2. **工具扩展**：若要处理网页研究、任意文件、代码或外部应用，增加经过授权与隔离的对应工具；技能本身不会提供这些能力。工具数量增长时再引入按需工具发现。
3. **任务级评测**：用真实模型回放通用问答、创作、修改、无关话题切换、错误恢复和提示注入场景，统计完成率与误调用，而非仅用模拟网关证明协议正确。

仓库根目录的 `AGENTS.md` 约束开发本项目的编程 Agent；GuGu 产品内的通用指令位于 `lib/agent/runtime.mjs`，技能位于 `agent-skills/`。
