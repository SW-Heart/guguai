# 作品检查

先确认用户要检查的是创意、画面、声音、连续性还是交付文件，以及作品原本要实现什么效果。只读本次相关版本，不把旧草案当成已确认内容。用户只要求审阅时交付问题和建议；用户要求修改时，在现有授权范围内修改受影响的文本或素材。

## 检查入口与交付

先取得当前作品、用户要求和必要参考，再选择取证方式。普通局部检查直接进行；完整作品检查、视频证据不足或需要交付结论时，读取 [证据与结论](references/evidence-and-verdict.md)。用户要求修订或复查时，读取 [局部修订方法](references/repair-playbook.md)，包含问题归属、具体示例和修改影响范围。

通过 `skills_read(name: creative-review, resource: 对应路径)` 读取；有 `nextOffset` 就读完同一文件后续页。检查表用于内部判断，对用户交付的是可定位的问题和可操作的改法。

本轮应得到以下一种结果：有证据的问题与修订建议；已执行的授权内修改及复查结果；或限定检查范围的“未发现明确问题”。材料缺失时明确指出缺哪个版本、画面或声音证据，仍可检查的部分继续完成。没有看到作品时只能审方案，不给作品合格结论。

每个值得报告的问题要说清：具体位置（段落、镜头、图片区域或视频时间）、实际看到/读到/检测到的证据、对观众或生成结果的影响，以及最小修订方向。优先报告阻碍理解、事实错误、人物或产品不一致、动作未完成、时长容不下对白、声音缺失、字幕错误等可定位的问题；不靠“缺少高级感”“AI 味太重”这样的标签代替证据。若只有风格偏好差异，标为可选建议。

## 先诊断，再修订

先核对是否完成作品目标，再检查因果与观看顺序、人物/空间连续性、画面与声音，最后考虑风格细节。把“意图不清”“描述自相矛盾”“模型未执行”和“素材已好但剪辑不当”分开：提示词中的正确指令不证明成片已实现，成片失败也不一定要重写故事。

涉及运镜、人物乱跑或镜头漂移时，用 `skills_read` 读取 `video-production` 的 `references/camera-and-blocking.md`。核对每次移动揭示什么，人物路线与摄影机路线是否相容，起止构图是否落实，以及推近/变焦、摇摄/横移、俯仰/升降是否混淆。抽帧不足以判断时先标明待核对范围。

修订建议包含可执行的替换文本或局部剪辑动作，以及修好后应看到的结果。例如“镜头 3 在人物停下后仍持续漂移；让摄影机随人物在门口停住，终点保持中景”，比“加强镜头感”更可验收。优先修影响理解与后续制作的问题；用户要求直接改稿时执行已有授权内的文字修改。已满足目标就停止润色，不以个人偏好反复返工。

## 按素材检查

- 文稿：用 `documents_read` 或项目当前版本核对人物目标、行动因果、对白可表演性、镜头职责和画面/声音是否覆盖关键信息。
- 图片：先 `assets_inspect` 看真实图像，检查主体、构图、文字、身份、造型及参考要求。未实际看到图片时只审提示词，不评价生成结果。用户反馈“不专业”“不够好看”时，按需要用 `skills_read` 读取 `image-design` 的 `references/critique-and-refinement.md`，把反馈转成有证据的局部修改；不把个人风格偏好当成错误。
- 视频：先 `video_probe` 确认时长和画幅；按问题位置用 `video_frames` 取帧，必要时用 `video_boundaries` 找物理切点。抽样帧只证明取样时刻，不证明中间动作或全片质量。
- 声音与字幕：`video_audio_check` 只能证明音轨和音量/静音，`audio_transcribe` 可提供台词时间与字幕候选；它们不能替代实际听审，也不能证明口型、音色、音乐和音效正确。对专名、数字和同步只报告已经核对的事实。

检查报告可以直接回复；用户需要保存时用 `documents_write` 写成可编辑文稿。对本平台生成的图像或视频，可用 `model_experience_note` 保存已经查看且能对应到生成任务的单次观察；参考视频或用户上传素材不属于模型实测案例。建议按“必须修正 / 可选优化”组织，涉及局部返工时点名受影响的镜头、素材或声音时段，并说明可保留哪些已成功内容。没有真实观察能力的部分列为待人工核对，不给虚构分数或合格结论。
