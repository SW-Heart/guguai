# 从需求到可制作的镜头

用于多镜头原创视频、已有剧本投产和部分素材续做。单镜头描述直接解决，不强制建立整片流程。

## 先选制作路径

| 已有条件 | 路径 | 下一步的有效产物 |
| --- | --- | --- |
| 只有主题，先要方案 | 内容目标、段落与拍法设计 | 时间安排和关键画面；不提交生成 |
| 已有剧本或认可方案 | 找齐已有素材，确认缺口 | 逐镜参考、动作和声音安排 |
| 已有可用视频 | 先判断素材能否完成目标 | 含入出点的剪辑安排，只补真正缺失镜头 |
| 部分镜头已生成 | 找回任务与素材，检查可用范围 | 复用成功镜头，处理剩余部分 |
| 用户只要提示词 | 将明确目标转换成可执行描述 | 提示词与真实所需输入；缺参考可列计划 |

没有目标模型也可以讨论创意；正式制作方案要主动推荐并核对模型，而不是留下整套设置让用户自行决定。用 `models_list`、`models_describe` 做只读查询，遵从用户指定或手动选择的模型。不要为填模型字段提前改变故事；缺少的模式、时长或声音能力应说明清楚，不静默换模型或降级要求。仅规划不调用 `media_prepare`、`media_submit` 或付费试镜。

## 让用户看懂制作设置

先说明成片用途和内容目标，再给本方案的制作设置；简单方案可用一句话，多段或设置有差异时再用表格。至少交代：

- **模型**：使用界面中的模型名称，给与本任务有关的选择理由。依据当前支持的参考方式、时长和设置判断；实际质量比较需要真实观察，不能凭名字宣称“效果最好”。
- **时长与次数**：成片总长、每次生成时长、生成次数、最终保留时长及必要裁剪；明确一个生成片段可以含多个镜头。
- **比例与画质**：例如“竖屏 9:16、720p”，并说明与发布场景的关系。用户已指定时保留，不能默认拉伸、裁切或升降画质。
- **生成方式与素材**：文字生成、参考素材或首尾帧；列本次实际使用的素材名称、职责和必要缺项，复用已绑定的角色。
- **声音与文字**：逐字台词及说话人、是否需要旁白/配乐/环境声/字幕；区分描述中的创作要求与当前工具真的支持的独立设置。
- **其他参数与费用**：只列当前模型提供且本方案需要的可调选项。有可靠单价时给有依据的估算，注明哪些待报价；没有报价不编金额，也不把生成额度当成全部成片成本。

同一套设置用于多段时写一次，各段只列差异；用户只问某一项时直接回答该项。未知的设置标为建议或待核实，不用内部字段名、线路名、资产 ID 或数据结构向用户解释。单段方案可写成“建议用〔当前可用模型名称〕，参考你的人物图生成一段〔支持的秒数〕视频，采用〔比例〕、〔画质〕，用于……；成片保留……，对白……”。括号只是写作示意，交付时用核实后的值，不能照抄占位符。

预算按当前实际计价方式、生成长度和次数估算，不能按最终剪辑片长推算生成费用。若每次生成较长片段再裁剪，应说明多生成部分也可能计费；试镜、补参考图与返工不是默认包含的额外任务。

核对参数组合，而非各字段单独存在：某画质或比例可能只在特定模式下提供对应时长，首尾帧必须有真实两帧；同一请求按同一组合验证。若目标片长与支持长度不一致，说明怎样裁剪或分段及其代价，不能把“生成 15 秒再剪成 10 秒”说成支持 10 秒生成。

## 区分三种时间

- 叙事时间：观众需要多久理解动作、听完话语、感受到反应。
- 生成时间：当前模型允许提交的片段长度。
- 剪辑时间：真实生成片段中最终保留的长度。

计划 3 秒插入镜头而模型最短生成 5 秒时，可生成后选择可用范围，不能强行填一个不支持的 3 秒参数。需要连续动作 12 秒而当前上限更短时，在能衔接的动作状态拆开，或提出符合目标的模型选择。不要靠加速把未完成动作伪装为完成。

制作表只保留本轮要用的内容：`片段及所含镜头 / 观看任务 / 生成时长与保留时长 / 起止动作与接点 / 台词与声音 / 已有素材与用途 / 待补素材 / 与统一设置不同的模型或参数`。模型、比例、画质和生成方式在表前统一说明；有差异才逐段列出。没有真实素材时写待补；不要用看似真实的 assetId 占位。

## 让付费任务有明确用途

先核对图像、人物、场景与动作输入的依赖：真正需要身份控制的镜头绑定已查看的角色图；不需要精确连续性的抽象画面不必先生成一整套设定。每个计划生成项应能回答“成片的哪一段需要它”和“怎样判断可用”。

多素材参考要写明职责与可变内容。参数由 `models_describe` 决定，进入制作后才用 `media_prepare` 核实本次输入、模式和报价。两者与预想不符时修计划并说明变化，不能把外部文档当能力承诺。提交前用自然语言说明本次模型、生成时长、比例、画质、具体内容和用途，接着调用 `media_submit`，按系统费用确认或预算执行。

有上下游依赖时先查看上游结果，再把真实 ID 交给后续镜头；彼此独立且已授权的任务可分别提交后统一 `jobs_wait`，不为了串行流程增加等待。无需为每次普通创作判断重新确认；改内容或增加任务时遵守当前授权范围。

## 原创示例：已有两个片段的 12 秒产品短片

已有片段为“拿起杯子”和“杯盖合上”，用户需要展示随身携带，不要旁白。

先检查两段的画幅、可用动作与杯子外观。可安排拿起、收进包、结尾产品三个观看任务；若已有素材缺少收进包这一动作，仅补该镜头。杯盖合上的片段可以提供产品细节，但不能据此宣传防漏、保温时长等未经提供的功能。片长按真实可用段调整，必要的静默和环境声不被默认音乐覆盖。

若收进包的动作生成后杯子变形，保留其他片段，只修这镜的身份参考与动作复杂度；若动作已好但开头等待太久，先剪掉等待，不重新生成。

## 继续制作与失败处理

保存每个镜头对应的准备请求、任务和结果素材，续做先读取这些记录。`jobs_wait` 未结束或状态不明确时继续核对，不能重提交来“催进度”。确认失败后定位是输入、能力、生成表现还是剪辑问题；调整有因果依据的变量再决定是否需要新的生成。

同一问题在一次针对性修订后仍出现时，重新评估镜头设计或参考条件，不盲目重复相同请求。无法在当前能力内满足关键要求时说明缺项并给有区别的选择；能够独立完成的已授权部分继续完成，不以一处缺项取消全部工作。
