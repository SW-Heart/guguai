# 模型提示词参考

本文件只指导创作表达。实际可用模式、时长、画幅、参考数量、画质、线路和报价始终以本次 `models_describe` 与 `media_prepare` 返回为准。供应商公开能力不等于 GuGu 当前线路已开放。用户指定模型时优先遵从；不支持目标时说明具体限制并给可执行替代方案。

## 通用结构

先写画面中可见的主体与场景，再写从起点到终点的动作、机位和节奏；有对白时把说话人、逐字台词、语言与表演放在发生的时段。声音与字幕分别决定，别用“自动生成声音/字幕”代替内容。参考素材逐个注明控制身份、外观、动作、地点、构图或声音哪一项；素材 ID 和顺序来自工具结果。

## Seedance 2.0 / 2.0 Fast / 2.5

需要 Seedance 专用优化时，用 `skills_read(name: seedance-creation-bible)` 读取「Seedance 2.0/2.5 创作圣经」，再按版本与任务读取其参考资料。

2.0 / 2.0 Fast 优先按“镜头1、镜头2”组织，不用精确时间戳控制剧情；2.5 可以使用连续的整数秒时间轴，仍需检查实际切点。参考模式按真实上传顺序对应素材，写明每份素材的职责；不得让自拍照背景覆盖目标场景。2.0 人物参考优先独立大头照加全身照，避免人物多视图拼图；2.5 可使用多视图，多人物时优先单视图或分开上传不同视角。2.5 的多素材和较长视频能力不能反推到 2.0，具体上限读当前目录。只有当前 GuGu 工具确实提供视频编辑、延长或独立音频引用参数时，才将外部文档里的这些模式当作可执行能力。

## MiniMax H3

需要 H3 专用优化时，用 `skills_read(name: minimax-creation-bible)` 读取「MiniMax 创作圣经」，按任务读取基础/关键帧、全参考、声画语法、原创模板或八类视频制作方法。官方结构与 GuGu 当前线路的适用条件见该技能的平台能力资料。

先区分当前模型 ID 和实际线路。`minimax-h3` 与 `minimax-h3-15s` 在 GuGu 的参考输入、画幅与画质范围可能不同，不能把官方 H3 的所有模式直接套到兼容或工作流线路。若当前线路支持首尾帧，按输入顺序给真实首帧与尾帧；若只支持普通参考，说明各图承担的角色，不把提示词中的“首帧”当成接口已绑定首帧。H3 的创作重点是画面、动作、对白和声场共同设计；对白保留用户原文并明确说话人。需要官方 H3 的专用结构时，先确认当前接口按该结构接收整条提示词，再按基础模式或全参考模式组织，不能把结构字段拆成多次生成。`minimax-h3-15s` 未验证该方言时使用清晰自然语言。

## Veo 3.1 与 Veo 3.1 Fast

适合从明确的场景、起始画面和一个主要动作出发写紧凑镜头；当终点构图必须落到某个已设计状态时，优先检查 `FIRST&LAST` 是否对该画幅开放，并绑定真实两帧。`REFERENCE` 和 `FIRST&LAST` 是不同模式，不能因为模型有两者就混填素材。对白、环境声与镜头运动写在同一次请求里，但仍需检查结果中的实际声音和终点。

## Grok、Omni Flash 与其他普通视频模型

Grok 可考虑用于需要较长动作推进的镜头，Omni Flash 可考虑用于短段试镜；具体时长和支持的画幅只看本次目录。使用明确自然语言说明主体、动作、空间、机位和声音，不猜供应商特殊标记、隐藏参数或精确文字能力。生成后按真实结果比较身份、动作、镜头和声音；同一提示词在不同线路的表现需要实际试镜，不能用模型名称推断质量。

## 动作迁移

若目录显示 `motion-retargeting` 可用，它的任务是让目标人物承接参考视频的动作，需要符合线路要求的人物图片和动作视频；不能把它当成普通文生视频或仅靠一段文字实现动作迁移。先检查图片、视频各自的控制范围以及输出画幅，再预检该线路。
