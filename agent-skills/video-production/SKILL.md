# 视频创作

先区分用户要的是创意讨论、可复制提示词、已有素材剪辑，还是实际生成成片。只讨论时给可修改的导演方案；只有用户已要求制作时才提交媒体生成。成片目标至少说明观看对象、传播场景、时长、画幅、信息或情绪终点，以及声音和字幕是否需要。不要把所有视频做成旁白加图片的固定模板。

## 从当前阶段开始

- 多镜头制作、现有剧本投产或部分镜头续做：读 [制作计划与素材依赖](references/production-planning.md)，明确本次交付、可复用素材与生成缺口。
- 需要制作方案、选模型或确定生成设置：同样读 [制作计划与素材依赖](references/production-planning.md)，方案中明确模型、成片与生成时长、比例、画质、生成方式和所需参考；不要等到用户点击生成才说明。
- 已有素材需要剪辑、混音、图文修改或最终文件：读 [剪辑与交付](references/editing-delivery.md)，区分源片时间与成片时间，以实际文件选择入出点。
- 导演处理、人物表演、光线、美术与效果设计：读 [导演、表演与画面](references/directing-and-performance.md)。
- 多段故事、继续已有视频、前后动作与声音衔接：读 [连续制作与续拍](references/continuation-and-state.md)。
- 只要单镜头提示词：直接设计该镜头，按需读下文镜头或模型专题，不扩展整片计划。

通过 `skills_read(name: video-production, resource: 对应路径)` 按问题读取。返回 `nextOffset` 时读完同一资源的后续页；不默认加载所有资料。已有作品先读当前文稿和真实素材，保留用户已决定的内容。

## 导演方案

用“开场抓住什么 → 中段怎样推进 → 结尾交付什么”建立时间线。每段写清观众新获得的信息或情绪、画面主体、动作/镜头变化、声音职责和预计时长。产品视频要把卖点变成可见证据；解说视频要让图像帮助理解而非重复旁白；叙事片要让人物行动引出后果。需要实拍素材或用户已有镜头时优先检查能否剪成作品，再决定是否补生成画面。

涉及品牌视觉、画面层级或系列美术统一时，可用 `skills_read` 按需读取 `image-design` 的 `references/visual-foundations.md`：把角色、字体、配色职责、材质与光线转成可保持的视觉锚点。视觉服务动作、节奏和观看终点，不把每个镜头做成同一张静态海报。

每次视频生成请求只放进该模型和时长能承载的动作与对白。描述起始状态、主体动作、运镜、终点、必要声音及不可改变的身份/场景。多镜头容器只在目标模型和当前线路明确支持时使用；否则拆成可独立生成并剪辑的镜头。用参考图控制身份、地点或构图时分别说明职责；首尾帧只有在工具提供该模式且两张真实素材齐备时使用。

同一场景的连贯动作和完整对白优先在模型支持的单次生成内完成。小幅运镜、景别变化、表情或换人说话不自动成为拆分理由；只有明确的场景变化、单次能力限制或用户要求才安排必要分段。镜头数不等于生成次数，后期拼接不能宣称连续长镜头。

## 镜头设计与场面调度

设计运镜、分镜或修正人物与镜头乱动时，读取 [运镜与场面调度](references/camera-and-blocking.md)。先明确观众看什么、站在哪里、怎样接近现场，再分别安排人物路线与摄影机路线。移动要揭示信息或改变观看关系；拿不准时考虑固定镜头。每镜明确起止构图、主体动作、运动方向和速度、跟随关系与停止条件，检查距离、焦距、人物大小和背景变化是否相容。

跨镜头策划、广告表达和剪辑节奏读取 [段落与连续性](references/sequence-design.md)。单镜头提示词无需展开整片流程。

## 选模型、写提示词

规划实际制作方案时就用 `models_list` 和 `models_describe` 读取当前可用模型、模式、时长、画幅、画质、参考素材上限及已提供价格；模型名称和外部资料不能代替当前平台能力。用户指定或手动选择的模型优先，其他情形给一个主推荐并说明与目标的关系；不要把选模型与配参数全部交回用户。比较效果时可用 `models_experience` 查看当前工作区已有生成案例；只有逐条观察能支持画面、动作或声音质量判断，样本少时不要排名。按目标选择：准确时长与多素材参考、人物和声音同镜生成、首尾状态约束、或较低成本试镜。只展示本方案需要的参数，并核对同一模式、画质、画幅与时长组合可用；提示词中的运镜、风格和声音要求不能伪称为独立参数。需要模型专门写法时读 [模型提示词参考](references/model-prompting.md)。用户要求开始制作后，`media_prepare` 验证本次请求与报价；已授权后 `media_submit`，保存任务和素材 ID。只要方案时不进入生成预检或付费试镜。

## 图文与补充画面

成片需要画中画、分屏、文字/商品揭示或元素动画时，用 `skills_read` 读取 `video-replication` 的 `references/video-editing.md`。`video_edit` 可在已有底片上编排图层并按目标台词定位；修改已有作品先 `video_edit_read` 取得原底片和方案，保留未变内容，避免反复烧入旧文字。

## 声音、剪辑、验收

声音先决定是人物原声、旁白、环境声、音效还是连续音乐；不为填满声轨而全部添加。已有视频原声与独立音频的处理、字幕时机及限制见 [声音与成片检查](references/audio-and-review.md)。实际制作的终点是可播放成片：必要时用 `video_compose` 裁剪和拼接真实片段，再检查时长、画幅、接缝、音轨、静音、对白、字幕和事实错误。技术探测与抽帧不能证明表演、音乐或口型已经正确；未做实际听看时明说需要人工核对。若检查了生成产物，可用 `model_experience_note` 保存有证据的单次观察，供以后在同一工作区参考。局部问题只返工受影响镜头或声轨，保留成功素材。

## 完成条件

用户要求镜头相接、续拍或反馈分镜不连贯时，先读 [连续制作与续拍](references/continuation-and-state.md)，按实际结尾决定下一镜起点，复用已确认的人物引用；不要只加一句“保持一致”。

策划请求交付能直接讨论和修改的方案；提示词请求交付可用正文及必要输入；成片请求继续到真实输出可读取，并说明已核对与未能核对的部分。用户只要求一个阶段就止于该阶段。反馈以画面、台词、素材和完成结果表达，工具字段与内部制作规则不进入作品文案。
