# 角色设计

依据故事、用途和用户指定风格，建立能被识别、表演和复用的角色。先读已有角色设定、剧本和真实参考，保留确认的身份、年龄、性格、外貌与关系；局部改服装或发型时不重建整个人物。

## 选择交付

文字人物设定交付完整可用设定；视觉角色交付外貌、服装、材质、配色、道具与必要视图；用户要求实际图片时结合 `image-design` 继续制作。参考图没有提供或无法查看时明确依据文字创作，不声称还原其外貌。角色设计请求不自动写整集剧本或生成视频。

人物的叙事功能、当前目标、选择方式、背景与关系应相容，但不为每个人强加创伤、秘密或反转。观众需要识别的视觉特征选择少量稳定锚点：轮廓、发型、面部特征、服装结构、配色职责、惯用道具。风格由用户或作品确定，不把所有角色都做成同一种美型人物。

## 保持一致，允许变化

分开记录稳定身份与本次状态。身份包括面部结构、体态和固定标记；状态包括服装版本、年龄阶段、表情、伤痕、持物和动作。用户指定换装或成长时允许状态变化，避免把所有旧特征都当成不能改变的约束。

多人分别绑定姓名和参考职责，不凭图片中心位置选人。前侧后视图维持同一角色、衣着、比例和道具；后视图看不到的细节不要凭空证明。表情变化保持身份，夸张程度按作品风格判断。多视图展示与下游模型的实际参考输入分开：角色展示可以同图，视频身份参考是否分图取决于所选模型。

需要可制作设定、多人、多视图或漂移修正时读 [角色设定与参考图](references/identity-and-views.md)，使用 `skills_read(name: character-design, resource: 对应路径)`；有 `nextOffset` 时继续读完。

## 制作与交付

实际设定图先查当前图像模型和真实素材，通过 `media_prepare` 报价，再按已有授权提交。查看真实结果后核对面部、轮廓、服饰细节、道具、视图和数量；未出图时交付文字与描述，不声称已验证一致性。图片成功后保留真实素材 ID，后续镜头复用这些素材，不能仅复用一段旧提示词。

需要保存设定时用 `documents_write`；需要角色节点时按最新项目 revision 用 `project_edit`，只改用户指定字段。故事或对白深入处理用 `script-writing`；短剧分集关系用 `short-drama`；人物运动、表演与运镜技巧用 `video-production`。
