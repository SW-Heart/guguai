# 剧本创作

从当前文本与用户目标开始，写可表演、可拍摄的剧本。区分完整成稿、故事方案、改编和局部修订；用户要求完整剧本时不以大纲替代，用户只改一场时保留其他场次。

## 原稿与范围

用 `documents_read` 或 `workspace_read` 取得当前稿、前段结尾及已锁定内容。改编时区分原作事实、用户允许的变化与新创作；长材料只对已读取部分作判断，不假称看完原作。明确体裁、观众体验、目标时长和结尾要求；已有信息够用就写，不为了填写格式反复提问。

短剧分集和持续追看节奏用 `short-drama`，通用场景、对白和结构以本技能处理。人物背景和关系在剧本中按需要建立；系统化角色外貌、服装和设定图用 `character-design`。实际视频拍法与制作读 `video-production`，剧本请求不自动生成图片或视频。

## 场景与对白

每场先确定谁在争取什么、阻力来自哪里、采取什么可表演策略，以及场末发生什么变化。变化可以是信息、关系、选择或行动后果，不强制每场都有反转、对抗或悬念。观察、表演、广告演示不硬补人物创伤或隐藏欲望。

用动作、停顿、递物、空间变化和声音承载可演出的信息。对白看它在争取、试探、回避、拒绝还是修复关系，依据人物经历与当时处境区分说话方式；不靠口头禅或解释性独白堆信息。用户逐字指定台词保持原文，需要改变时说明理由。

按内容选择清晰的场景标题、行动段和对白格式，避免把全部摄影参数写进文学剧本。必要镜头与声音说明只用于无法由行动表达的关键信息。按表演、动作、停顿估时，不按字数平均切镜。

需要场景实例、对白修订和结构诊断时读 [场景与改稿](references/scenes-and-revision.md)，使用 `skills_read(name: script-writing, resource: 对应路径)`；有 `nextOffset` 时继续读完。

## 交稿与修订

检查行动是否导致后果、信息揭示是否有依据、人物选择是否成立、对白能否在目标时长表演。保留原创选择，不把个人偏好当成结构错误。用户需要保存时用 `documents_write`；修改已有作品使用当前 revision，冲突先重读再局部修订。交付请求范围内完整稿件，说明必要的新增选择；不将内部分析表、工具字段和改稿规则写进作品。
